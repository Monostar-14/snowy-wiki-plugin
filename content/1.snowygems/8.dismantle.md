# 查看与拆卸宝石

`/sgem inspect` 只读查看主手装备的宝石；`/sgem dismantle` 打开收费拆卸界面。两个界面都分页显示，查看不会触发拆卸。拆卸时请主手只拿 **1 件装备**，检查图标上的费用和损坏率后左键点击。

## 拆卸流程

1. 验证主手槽位、物品内容与打开界面时一致，并确认宝石仍存在。换手持物品或物品被其他插件修改后，需要重新打开。
2. 检查并扣除费用。经济接口报告失败时停止，保留装备与宝石。
3. 在装备副本上撤销一颗宝石的已记录效果。撤销失败时保留原装备，尝试退还费用；退款失败会提示联系管理员。
4. 写回装备，再按 `BreakChance` 判定是否返还宝石。损坏只影响宝石返还，不影响已经完成的拆卸。背包满时返还宝石会掉在玩家身边。

同 ID 强化石允许重复使用。新镶嵌会逐颗记录，拆卸同 ID 时先拆最近镶入的一颗；点击任意同 ID 图标都是这一规则。拆完自动刷新，最后一颗拆完后会提示没有已镶嵌宝石。

## 费用配置

```yaml
Dismantle:
  Cost:
    Enabled: true
    Type: money
    Amount: 100
  BreakChance: 20
```

| 配置 | 行为 |
| --- | --- |
| `Cost.Enabled: false` | 免费拆卸 |
| `Type: money` | Vault 金币，需要 Vault 和经济插件，可使用小数 |
| `Type: points` / `point` | 内置点券或 PlayerPoints，由 Points.Provider 选择 |
| `Type: exp` / `explevel` / `level` | 经验等级，不是经验点数 |
| `Amount` | 非负有限数；点券和经验向上取整，例如 0.1 收取 1 单位 |
| `BreakChance` | 夹在 0～100；0 必返还，100 必损坏 |

费用类型拼错、负数、非有限值或超出整数范围的点券/等级费用，会禁止收费拆卸并报告配置错误，不会默认为免费。`Amount: 0` 明确表示免费。修改后执行 `/sgem reload` 并重开菜单。

完全免费且无损的配置：

```yaml
Dismantle:
  Cost:
    Enabled: false
  BreakChance: 0
```

## 哪些效果能够撤销

| 奖励 | 本次更新之后新镶入的宝石 |
| --- | --- |
| `Attribute` | 按本次实际增量扣回，保留同属性的其他已记录贡献；新属性累计按属性、运算方式、槽位区分 |
| `Enchant` | 按实际等级变化撤销，而非无条件删除整个附魔 |
| `LoreAdd` / `LoreReplace` | 记录新增行或单行替换，撤销匹配的局部修改，保留其他行 |
| `Conditional` | 仅在内部奖励实际成功时记录并撤销内部奖励 |
| `LoreVar` / `Name` / `Unbreakable` 等其他修改 | 尚无通用自动撤销，请按具体配置设计移除逻辑 |
| `Point` / `Money` / `ItemGive` / `MaxHealth` / `ExpLevel` | 已发出的玩家奖励不会追回 |

后续宝石清除或定级了同一附魔，可能使较早宝石的撤销无法成立。这时先拆较新的覆盖型宝石，避免错误恢复等级。若其他插件已改写目标 Lore，插件不会用整份旧 Lore 覆盖当前内容，无法匹配的局部修改可能保留。

本次新增的技能符文通过两条 `LoreAdd` 写入闪现标记和距离，新镶入后拆卸可撤销这两条新增内容。以 Lore 触发的 BUFF 停止续期后，已经施加的药水效果要等现有持续时间结束。

### 旧装备的边界

旧版本只记录宝石 ID，重复同 ID 会合并，无法事后恢复“到底强化了几次”和每次增量。旧装备没有新历史时仍走兼容撤销：属性可能清除该旧累计值，附魔按旧规则撤销，旧 Lore 不自动回溯。**不要把旧装备的拆卸结果当成新记录机制的验证结果。** 在测试服用新获得装备重新镶嵌后验证，并保留正式装备备份。

历史里保存的是实际成功时的奖励参数，之后改奖励配置不会改写这份历史；宝石 ID 的配置仍须存在，才能显示图标并执行移除提示和 `$onRemove`。历史损坏时拒绝拆卸，保留物品。

### `$onRemove`

新镶嵌的 LoreAdd/LoreReplace 不要再手写删除相同标记的奖励，否则自动撤销后再次删除可能影响另一颗同名宝石。

自动撤销后仍执行当前配置中显式标记 `$onRemove` 的奖励。它们不会被误当成当初的镶嵌效果来撤销。适合额外返还材料，但不应作为可靠的收费关卡：某条奖励失败不会阻断整个奖励列表。统一费用请用 `Dismantle.Cost`。

## 排错

- 提示物品改变：重开 `/sgem dismantle`，检查是否更换主手或有其他插件编辑装备。
- 未返还宝石：先看损坏提示及 `BreakChance`，再检查身边掉落物。
- 撤销失败：开启 `/sgem debug Reward,GemManager,Dismantle`，检查历史、属性解析以及后续覆盖型附魔；失败会尝试退款。
- 退款失败：保存日志与实际余额记录，联系管理员人工处理；不要反复点击。
- 同属性仍有加成：可能来自其他宝石、原版装备属性或其他插件，拆一颗不等于移除所有加成。

权限为 `snowygems.inspect`、`snowygems.dismantle`，默认随 `snowygems.user` 提供。详见[权限节点](/snowygems/permissions)。
