# 游戏内编辑器

使用 `/c editor`，权限 `companions.admin.editor`，默认 OP 拥有。管理员有独立草稿，不会每点一次字段就立即改服务器配置。

## 创建与编辑

1. 点击列表中的随从，进入编辑草稿。列表和字段均可翻页。
2. 点击字段后界面关闭，在聊天中输入新值；输入 `取消` 返回。
3. 点击“保存并应用”，校验成功才保存到 `companions.yml` 与 `gui/companions.yml`。
4. 保存时正在召唤的该随从会收回，重新召唤查看效果。

“创建随从”以列表第一份随从为模板；“复制创建”复制当前草稿。新标识以小写字母开头，只含字母、数字、下划线，最多 48 字符，不能使用 `none` 或已有标识。
复制后会设置独立默认显示名称，但其他字段继承模板，应检查能力、价格与描述后再保存。

## 输入格式

| 字段类型 | 输入方式 |
| --- | --- |
| 名称、材质、贴图、能力 | 输入完整字符串；颜色使用 `&` |
| 布尔值 | `true` 或 `false` |
| 角度、数量、RGB | 整数；数量 1–64，RGB 0–255 |
| 位置偏移 | 有限数字，编辑器限制在 -32 到 32 |
| 价格 | 非负整数，硬币在末尾加 `C` |
| 描述列表 | 用 `|` 分隔；连续两个竖线表示中间空行 |

当前编辑器只能逐项修改模板已存在的叶子字段，不是任意 YAML 结构编辑器；新增身体部件等嵌套结构应在文件中处理。
部分较长 Base64 可能超出客户端聊天长度限制，此时直接编辑配置文件更合适。
材质按当前服务端校验，保存前还检查模型数据、头颅贴图格式及商店名称冲突。不会自动生成资源包。

## 草稿与多人编辑

直接关界面会保留草稿，再次 `/c editor` 可继续。点击“放弃草稿”或离开服务器会清除未保存内容。
保存前会对比配置快照与文件修改时间；其他管理员保存、执行重载或外部编辑导致配置变化时，拒绝覆盖，需要放弃旧草稿后重新打开。

## 删除与恢复

点击删除后进入二次确认。确认后删除随从定义和图标，收回在线玩家正在使用的该随从；玩家历史拥有记录保留。
至少保留一个随从模板。删除后若恢复同一标识，原来的拥有者仍可使用。

每次保存前备份 `companions.yml.bak` 和 `gui/companions.yml.bak`，这些备份会在下次保存时更新。
要恢复上一版，停服并成对恢复两份备份，不能只恢复一份。编辑器保存失败时查看后台日志，不要仅凭界面关闭判断成功。
